PMA AUTHENTICATION FIX

Scope of this update: authentication/login and email verification only.

Changes:
- Existing accounts are NOT required to sign up again.
- Every explicit login (including administrator login) requires a fresh 6-digit email verification code.
- Password is checked first; only the correct account can request a code.
- Verification is completed through /api/auth/verify-email and returns a signed session token.
- Signup sends the first verification code.
- Resend verification is available.
- Existing accounts remain in the database with their existing PMA ID, role, password and account data.
- Admin role is preserved; an admin account does not become a normal user.
- Page reload/session restoration remains token-based and does not require signup.

IMPORTANT DEPLOYMENT SETUP:
Configure email delivery on the backend (Render environment variables) before testing login:

Resend option:
PMA_EMAIL_FROM=verified@yourdomain.com
RESEND_API_KEY=your_resend_api_key

OR SMTP option:
PMA_EMAIL_FROM=your_verified_sender@example.com
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=your_smtp_username
SMTP_PASSWORD=your_smtp_password
SMTP_TLS=1

PMA_EMAIL_VERIFY_TTL=900

If email delivery is not configured, login will now show a specific configuration error instead of the generic "Please try again in a moment." message.
