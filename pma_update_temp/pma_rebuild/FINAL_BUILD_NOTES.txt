IMPORTANT LOGIN FIX
- The backend now seeds the configured administrator account if the local database is empty.
- Login transactions use SQLite WAL/busy timeout/retries and do not perform push-network work inside the login write transaction.
- The frontend no longer deletes the saved login token on every page load; it restores the session from /api/auth/profile.
- The administrator credentials are controlled by PMA_ADMIN_EMAIL / PMA_ADMIN_PASSWORD. Change the password after first login from My Profile.

RENDER DATA NOTE
Render services have an ephemeral filesystem by default. SQLite data can disappear after restart/redeploy on a Free service. For persistent academy data, connect the backend to Render Postgres or use a supported persistent storage configuration.

SEPTEMBER 23 REBUILD — FRESH ENTRY CONFIRMATION
- Sniper confirmation now uses the most recent fully CLOSED trigger candle, never an in-progress candle.
- A BUY/SELL confirmation requires the rejection/engulfing evidence from the closed candle.
- Confirmation expires after the next trigger-timeframe candle closes.
- If price has already travelled materially away from the confirmed close, the setup is marked LATE ENTRY BLOCKED and no entry/SL/TP is issued.
- The UI now shows a five-step setup timeline: Context → 50–61.8% Zone → Rejection → Candle Close → Entry.
- Day Trade BUY/SELL text uses separate mature directional colors and a white status badge, independent of the card's profit/loss background.
- Notifications use the same directional text treatment.
- Late entries are explicitly surfaced as blocked instead of being converted into a stale trade.
